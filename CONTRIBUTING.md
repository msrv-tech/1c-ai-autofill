## Как внести вклад

Спасибо, что хотите помочь проекту. Здесь — короткие правила, чтобы PR проходили быстро и без лишней боли.

### Где что править (главное правило)

- **`core`** — ветка разработки (ядро): общая логика, формы, модули. Большинство изменений делаем здесь

- Ветки конфигураций (`UNF_Rozn`, `UNF_Rozn_Fresh`, `UT_KA_ERP`) — это **сборки/адаптеры**. Они периодически мержат **`core`**.

Подробно про поток разработки и разрешение конфликтов: [`docs/MERGE.md`](docs/MERGE.md).

### Как предложить баг/идею

- **Баг/фича**: создайте issue в GitHub.
- **Обсуждение**: можно начать с Discussions (если включено).

### Быстрый старт локально (для разработки/проверки)

1) Склонируйте репозиторий и откройте worktree `main`.

2) Создайте `.env` в корне worktree (рядом с `xml/`), например:

```ini
1C_CONNECTION_STRING=File="D:\path\to\your\base";
1C_PLATFORM_EXE=C:\Program Files\1cv8\8.3.27.1859\bin\1cv8.exe
```

3) Запустите автоматизацию (сборка/загрузка/обновление/запуск):

```powershell
.\automation\update-extension-and-run-db.ps1 -BuildFromXml
```

Документация по параметрам: [`automation/README.md`](automation/README.md).

### Рекомендации по PR

- **Один PR — одна задача**: так проще ревьюить и мержить.
- **Не меняйте `xml/Configuration.xml` в `main` без необходимости** (версию — только когда это осознанно нужно).
- **Если правка специфична для одной конфигурации**, делайте её в соответствующей ветке и опишите это в PR/issue (почему нельзя в `main`).
- В описании PR добавьте:
  - что изменилось и зачем;
  - как проверяли (какая конфигурация/ветка, какой сценарий).

### Идеи для первого вклада

Посмотрите issues с метками **good first issue** и **help wanted**.
